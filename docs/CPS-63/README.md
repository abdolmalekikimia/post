# CPS-63: دریافت رویداد عملیاتی از Edge و اعتبارسنجی ساختاری مجموعه بارکدها

مستندات و سناریوهای آزمون اعتبارسنجی ساختاری ورودی سامانه Core (Gateway / Ingestion Pipeline) و بررسی سازگاری چند بارکد یک مرسوله بر اساس قواعد رسمی کسب‌وکار کارفرما.

---

## 🎯 اهداف بیزینسی و قوانین بارکدها (Business Rules)

1. **طول‌های مجاز:** فقط بارکدهای کاملاً عددی با طول‌های **۱۴ رقمی**، **۲۴ رقمی** و **۳۷ رقمی** مجاز هستند.
2. **یکتایی و برابری بارکدهای ۲۴ رقمی:** اگر چند بارکد ۲۴ رقمی برای یک مرسوله ارسال شود، مقدار همه آن‌ها باید یکسان باشد.
3. **تطابق پیشوند ۳۷ رقمی با ۲۴ رقمی:** اگر بارکد ۳۷ رقمی وجود داشته باشد، ۲۴ رقم ابتدایی آن (`barcode37[:24]`) باید دقیقاً با بارکد ۲۴ رقمی برابر باشد.
4. **عدم ناسازگاری ۱۴ رقمی:** وجود همزمان بارکد ۱۴ رقمی با بارکدهای ۲۴ یا ۳۷ رقمی به‌عنوان **داده ناسازگار (Inconsistent Barcode Set)** شناسایی و درخواست رد می‌شود.
5. **اعتبارسنجی سبک و بدون Side-Effect:** اعتبارسنجی در ورودی سامانه بدون تغییر دامنه‌ای یا ایجاد Aggregate انجام می‌شود.
6. **رهگیری Correlation-ID:** حفظ شناسه پیگیری در کل زنجیره.
